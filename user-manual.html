1. System Overview

The Field Tracking System is a web application for managing field employees, attendance, GPS location logs, client visits, task assignment, sales targets, travel allowance, leave management, payroll, employee identity codes, and operational reports.

The system is designed for mobile field use. Attendance and meeting pages use the device camera and GPS. Managers, HR, and Admin users use the same system for approvals, audits, master data, reports, payroll, and configuration.

6. Daily End-User Workflow

  1. Log in with the email and password provided by Admin.
  2. Open Daily Attendance, allow browser location and camera permissions, capture selfie and odometer photo if required, then check in.
  3. Keep the application open or active enough for background location sync while checked in. Tracking logs only while the session is checked in.
  4. Open Daily Tasks to view assigned site visits and in-house tasks. Accept, update, submit, or complete tasks as applicable.
  5. Open Client Meetings for each visit. Capture selfie, allow GPS, enter client/facility/department/meeting details, and submit the meeting log.
  6. Check Travel Allowance to review today’s calculated distance and allowance.
  7. At the end of the day, return to Daily Attendance, capture checkout photo/odometer, and check out.
  8. Use My Leaves for leave requests and My Payslips for payroll records.

The dashboard is the first page after login. It summarizes attendance, employee count, distance, meetings, trends, performance thresholds, and overdue tasks according to role.

Daily Attendance /attendance

All usersAdmin/Manager management view

Screenshot placeholder: Attendance check-in/check-out page with selfie modal, odometer modal, GPS status, and action button.

Executives and staff use this page to mark daily attendance. Admin and Manager are taken to the attendance management view by default; they can use /attendance?mode=self to mark their own attendance.

How To Check In

  1. Open Daily Attendance.
  2. Allow browser location permission.
  3. Open the selfie modal, capture your selfie, and confirm.
  4. Capture odometer photo if required, enter odometer reading, and vehicle/ticket details.
  5. Wait for GPS/address capture, then press Check In.

How To Check Out

  1. Return to Daily Attendance after work.
  2. Allow GPS and capture checkout selfie/odometer if prompted.
  3. Press Check Out. Travel allowance is recalculated after checkout.

Limitations: Camera and GPS must be allowed in the browser. Accuracy above the configured threshold may be ignored. Upload folder permissions must allow image saving.

AdminManager

Screenshot placeholder: Team live monitoring map/list showing active, inactive, checked out, on leave, absent, and logged-in-not-checked-in users.

Live Tracking shows team location status and route information. Location logs are created in the background only while a user is checked in and has granted GPS permission.

My Leaves

9. Limitations And Rules

  • Passwords cannot be recovered because they are securely hashed. Reset passwords through Admin User Management.
  • Camera and GPS functions require browser permission and a compatible device.
  • Background tracking logs only while the user is checked in and the browser can access location.
  • Location logs with poor accuracy may be skipped. The default maximum accuracy threshold in configuration is 100 meters.
  • Travel allowance depends on check-in/out data, meeting location data, GPS route logs, configured rate per KM, and map service availability.
  • Managers are generally restricted to assigned team members. Admin has full visibility. HR has broad HR/payroll/reporting visibility but not all Admin-only settings.
  • Some exports are CSV downloads; some PDF options are print-friendly HTML pages opened in a new tab.
  • Attendance and meeting media can be permanently deleted by authorized delete actions or retention cleanup.
  • Old attendance and meeting data may be subject to the 60-day cleanup retention policy.
  • Deleting users or master records can affect historical references. Prefer disabling users when history must remain intact.
  • The top search box is a common header element and may not perform global search across all modules.
